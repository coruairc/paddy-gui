## Component Specs

### Permission prompt card (inline, in thread)

- Location: rendered inline in the message thread, below the assistant turn that triggered it (not a modal).
- Container: `rounded-2xl bg-elevated px-4 py-3 shadow-[var(--shadow-border)]`, with `rise-in` entrance.
- Header label: mono 10px uppercase accent — "permission" or "question".
- Title line: 14px fg — "Paddy wants to" / "Paddy is asking".
- Subtitle: 12px muted — `prompt.title`.
- Detail: `pre` block, `rounded-lg bg-bg p-3 font-mono text-xs`, `overflow-auto`, max-height 240px (scroll inside).
- Actions row: `flex flex-wrap gap-2`, mt-3.
  - Deny: `Button size="sm" variant="danger"` → "Deny".
  - Always (permission only): `Button size="sm" variant="outline"` → "Always".
  - Allow/Answer: `Button size="sm"` (accent) → "Allow" / "Answer".
- Interaction: clicking any action disables all three buttons until the reply resolves (pending state: buttons `disabled`, label becomes "…"). On success the card is removed from `prompts` (permission-cleared echo). On deny, a muted thread line is appended: "Permission denied — run aborted." (role: system, 12px muted).
- Question kind: "Answer" opens an inline text input (not `window.prompt`) — a single-line `Input` with submit on Enter; empty submit is a no-op. This replaces the current `window.prompt` anti-pattern.
- Accessibility: card is an `<article>` with `aria-labelledby` pointing at the title; buttons have visible focus rings.

### Optimistic message bubble

- On submit: append `{ id: "local_<timestamp>", role: "user", text, created, activity: [], pending: true }` to messages.
- Styling: same as a confirmed user bubble, plus a pending indicator — a 6px accent dot with `pulse-live` at the trailing edge of the bubble, opacity 0.7.
- Reconciliation: when a server-echoed user message arrives via `mergeMessage`, match by (role === "user" && text === temp.text && |created - temp.created| < 5000ms); replace temp id with server id and clear `pending`.
- On send error: remove the optimistic bubble and restore `text` to the composer draft; set error state. Do not leave a duplicate.
- Duplicate submit guard: submit button and Enter-to-send are disabled while `working === true` or while a pending optimistic bubble exists; ignore duplicate `submit()` calls (early return).
- No second bubble on retry: retry reuses the existing session and does not re-append an optimistic bubble.

### Settings → Connection form

- Fields: URL (`Input` placeholder "http://127.0.0.1:4096"), Username (`Input` placeholder "Username"), Password (`Input type="password"`).
- Password placeholder: when a stored password exists, placeholder is "•••• (stored)"; otherwise "Server password". The field starts empty.
- Save semantics: empty password field preserves the stored password (client sends nothing/empty; server only updates when non-empty). Non-empty replaces. After save, clear the field and show note "Saved. Reconnect to apply." in `text-ok`.
- Clear password: a separate `Button variant="outline"` labeled "Clear password" (shown only when a stored password exists, i.e. `hasConnectionPassword`). Clicking opens a confirmation ("Clear the stored OpenCode password?") then calls settings with an explicit clear flag and shows "Password cleared." in `text-ok`.
- Reconnect button: `Button variant="outline"` "Reconnect" beside Save.
- Status lines: auth-required → `text-warn` "OpenCode is running, but this controller needs its password."; not installed → `text-danger` "OpenCode was not found on PATH. Install it, then reconnect."
- Layout: `max-w-md space-y-3`, inputs full width.

### Error states

- Thread send failure: inline banner above composer — `text-sm text-danger` with "{error detail}. Try again or reconnect." plus a "Retry" button (accent, sm) when a session exists.
- Connection lost: top bar `bg-warn/15 text-warn` "Disconnected. Reconnecting…" with spinner; working state cleared.
- Auth required: connection form warning (above) + password field focused.
- Not installed: danger line (above) + Reconnect disabled until binary present.
- Permission reply failure: toast via sonner (already mounted) — "Could not reply. Try again." and re-enable card buttons.
- Resume/reload failure: thread shows "Could not load messages. Retry." with a Retry button.

### Stop / retry / resume

- Stop: `Button` with `Square` icon (icon size) visible while `working`; calls abort, sets working false.
- Retry: `Button variant="secondary" size="sm"` "Retry" shown when last run errored and a session exists.
- Resume after browser restart: on bootstrap, if a stored session id exists, fetch messages and diff; show a centered spinner ("Loading session…") until first message arrives; then render thread. No duplicate turns — server is source of truth.
