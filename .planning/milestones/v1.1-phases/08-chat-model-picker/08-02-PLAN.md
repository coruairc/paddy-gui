<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| controller → browser | Catalog strings (name, id, providerID) are rendered into DOM ids and ARIA labels, then into visible text |
| browser local state → DOM ids | Model keys contain `/` and other punctuation; ids must stay unique and valid |
| persisted state → UI | A stale or hand-edited `deskModel` must not be presented as runnable |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-8-05 | Tampering | Option/group DOM ids and `aria-activedescendant` built from model keys (`model-picker.tsx`) | medium | mitigate | `modelSlug` maps every character outside `[A-Za-z0-9_-]` to `_`; keys are `providerID/id`, so `aria-activedescendant` always resolves to exactly one element |
| T-8-06 | Spoofing / integrity | Stale persisted `deskModel` shown as the runnable model | high | mitigate | `resolveActiveModel` membership check gated on `catalogLoaded` (no warn state before the fetch, so a reload with a saved model is not falsely flagged) → fall back to OpenCode's default, warn icon + `aria-describedby` + stale banner, and no automatic state write; 08-01's `modelForSend` sends the effective key, never the stale one; only catalog entries are selectable |
| T-8-07 | Information disclosure | Option text from catalog (names/ids) rendered into the DOM | low | accept | Values are already projected and redacted server-side in 08-01; React escapes text nodes |
| T-8-SC | Tampering | npm/pip/cargo installs | high | mitigate | No installs this phase — zero new dependencies; `package.json`/`package-lock.json` are not modified |
</threat_model>
