<objective>
Deliver the model-catalog data path end-to-end and prove it with the picker's thinnest working slice: OpenCode `GET /api/model` → `OpenCodeClient.listModels()` → projected and redacted `GET /api/models` → mirrored `DeskModel` + `api.models()` → a header trigger whose popup lists the catalog and applies a pick, persisted through Phase 7's `deskModel`.

Purpose: this is the phase's vertical spine. Every later task (keyboard, metadata, reconciliation, resume) hangs off this proven contract, and the projection is the security control that keeps account-shaped identifiers out of the browser.

Output: two adapter methods, one controller route, one browser client method and mirrored type, one pure helper module with tests, one picker component, and the header/composer/persistence wiring in the desk.

Decision trace (08-CONTEXT.md §Implementation Decisions):
- "Model Catalog Data Path": dedicated `listModels()` → `GET /api/models`; flat `{ models, default }` whitelist projection; key = `providerID/id` (entry id, first-slash split); disconnected answers 200 `{ models: [], default: "" }`; fetched on picker open with a 30s cache, no bootstrap fetch.
- "Selection, Persistence, Trust": persist immediately on selection through `PATCH /api/settings` body key `deskModel`; no eager model POST; the existing send path applies the model.
- "Picker Experience": trigger in the chat header, always visible when a project is selected, grouped by provider with live filtering (full keyboard lands in 08-02).
- MODEL-03 metadata is carried by the projection (`status`, `limit.context`, `time.released`) and rendered in 08-02.
</objective>
